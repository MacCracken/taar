# P(-1) review — 2026-11-08 (0.6.2)

**Scope.** All of taar as it ships after the toolchain bumps of 0.5.2 – 0.6.1
(cyrius 6.6.2 → 6.7.18):
- the bundled modules, `src/ipv4.cyr`, `src/socket.cyr` (both arms) and
  `src/dns.cyr`;
- the unit suite, the integration harness and the smoke programs;
- both CI workflows;
- the docs.

This is taar's first filed audit. The question it answers is what is wrong,
missing or untested in what taar already ships. New modules are out of scope:
the growth rule still gates them.

**Method.** The P(-1) steps, in order:
0. **Intent.** Read the roadmap and CHANGELOG, and checked GitHub issues (none
   open).
1. **Cleanliness.** `cyrius audit` (fmt, lint, docs, tests).
2. **Benchmark baseline.** taar had no benchmarks. `benches/codec.bcyr` was
   written and run three times before any repair.
3. **Internal deep review.** Every line of the three modules, the tests, the
   harness and CI. A second, independent review ran in parallel without seeing
   these findings, so it could not anchor on them. It found no out-of-bounds
   access, matching this review's own trace, and contributed findings C, E
   (AGNOS half), F and I, plus the hop-loop test gap in O.
4. **External research.**
   - glibc and musl stub-resolver behaviour: fallback nameserver, nameserver
     count, owner-name checks;
   - RFC 1035, 2181, 5452 and 7766;
   - Linux socket semantics: `connect(2)` honours `SO_SNDTIMEO`, not
     `SO_RCVTIMEO`, and `recvfrom` is not restarted after a signal while a
     timeout is set;
   - the agnos kernel source, to confirm the byte layout of the `udp_recv#53`
     `addr_out` record before writing code that depends on it.
5. **Repairs.** Each behavioural fix has a test that fails without it. Every
   new guard was **mutation-checked**, 18 in all: remove it, see the suite go
   red. Fixes that need a network have an integration case, which failed before
   the fix.
6. **Post-repair benchmarks**, the full gate set, and a consumer check: the
   0.6.2 bundle built by cyrius 6.6.2, which all three consumers still pin.
7. **Documentation audit.**

**Result.** 17 findings: none critical or high, 3 medium, 11 low, 3 info. All
are fixed in 0.6.2. Ten further items are deferred to the roadmap with their
reasons; see *Deferred*.

| # | Severity | Area | Finding |
| --- | --- | --- | --- |

## Findings

**A — silent public-resolver fallback.** `_taar_resolv_parse` returned 0 both
for "no nameserver line" and for "nameserver lines, none usable", and
`_taar_resolv_discover` sent both to 8.8.8.8. So a host whose resolv.conf lists
only IPv6 resolvers (or `0.0.0.0`) had every hostname sent, in cleartext, to a
third party. That bypasses a VPN's, a split-horizon or a filtering resolver.
`nameserver 0.0.0.0` also stopped the scan before a later valid server.
*Fix:* the parser returns -1 for "configured, none usable", and the decision
moved into the pure `_taar_resolv_choose`, which **fails closed** for that case.
A file that names no nameserver, or no file at all, still falls back. Whether
that default should be 127.0.0.1 (glibc, musl) is an open decision (roadmap
0.8.x).
*Tests:* `resolv-parse` and `resolv-choose`.

**B — unbounded TCP connect.** `taar_tcp_set_timeout_ms` set `SO_RCVTIMEO`
only, but Linux bounds `connect(2)` (and blocking `write(2)`) by
`SO_SNDTIMEO`. A truncated UDP reply from a resolver whose TCP/53 drops SYNs —
a common firewall misconfiguration — held the resolve through the kernel's
SYN retries. The same applied to whirl's HTTP connects, which ask for 10 s.
*Fix:* the function sets both options. A connect that times out fails
-EINPROGRESS; a send that writes nothing returns `_TAAR_ERR_TIMEOUT`.
*Tests:* `socket-send-timeout` (fills a socketpair; unfixed, it hangs until the
runner's timeout) and the integration case `tc_blackhole`. That case uses a
listener with a full accept queue, so the kernel drops SYNs with no firewall
tooling. Before the fix it ran past its 30 s case timeout; after, it falls back
at the 5 s deadline.

**C — AGNOS reply source unchecked.** The agnos kernel delivers a datagram to a
UDP listener by destination port alone (`net_handle_udp`), and taar passed no
`addr_out`. An off-path forger therefore needed no source-address spoofing,
only the 14-bit port and the 16-bit ID. The resolve docs claimed the kernel
dropped other senders, which is true only of the Linux connected socket.
*Fix:* AGNOS `taar_udp_send` records the peer, and `taar_udp_recv` drops any
datagram whose recorded source differs, as `connect(2)` makes Linux do. The
byte layout was confirmed in the kernel source before writing code that
depends on it: the source ip at +0 in taar's packed form
(`net_ingress.cyr:358`) and the port at +8 (`net.cyr:575-576`).
*Tests:* the match logic is the pure `_taar_peer_match` (`peer-match`). The
wiring is compile-only until roadmap 0.7.0. The kernel's one-datagram mailbox,
where a later arrival overwrites an earlier one, is kernel-side and not
fixable in taar.

**D — cut resolv.conf line.** The file is read into 4 KB. A `nameserver
10.0.0.12` line straddling the boundary arrives as `10.0.0.1`, a well-formed
wrong server. *Fix:* when a read fills the buffer, only complete lines are
parsed (`_taar_resolv_complete_len`). If no usable server is left, the resolve
fails closed. *Test:* `resolv-choose`.

**E — TCP retry bounds.**
- *Reads.* Each `recv` restarts its 5 s timeout, so a peer sending one byte
  every 4.9 s could hold a 2 KB reply for about 2.8 h. *Fix:*
  `_TAAR_DNS_TCP_MAX_READS = 16`. *Test:* `dns-tcp-read-cap` uses a
  `SOCK_SEQPACKET` socketpair, which keeps message boundaries, so it is a
  deterministic one-byte-per-read peer.
- *Sends.* AGNOS `sock_send#48` returns 0 after about 8 s without ACK progress,
  and the spin cap was 64. *Fix:* the cap is 1, so the worst case is about 16 s.
  Linux never returns 0 here.

A true per-resolve deadline needs a monotonic clock the consumers' stdlib does
not carry (roadmap 0.8.x).

**F — CRLF.** A token ended only at a space or tab, so `1.2.3.4\r` failed
`ipv4_parse` and the file read as unusable. *Fix:* CR ends a token too.
*Test:* `resolv-parse`.

**G — record class.** `_taar_dns_first_a` checked TYPE and RDLENGTH but not
CLASS. *Fix:* only class-IN records count. *Test:* `dns-answer-class`.

**H — AGNOS timeout 0.** The poll loops computed `deadline = now + timeout`
and looped `while (now < deadline)`. With 0 they never polled at all and
returned `_TAAR_ERR_TIMEOUT` at once. *Fix:* the pure `_taar_poll_deadline` /
`_taar_poll_expired` make 0 mean "no deadline". The loops poll at least once,
and a negative timeout is refused, as Linux refuses one. *Test:* `poll-deadline`
(pure). The wiring is compile-only.

**I — AGNOS send count.** `udp_send#52` reports the frame length. *Fix:* return
`pkt_len` on success, as Linux `write(2)` does. Compile-only.

**J — ignored timeout results.** If `setsockopt` had failed, the following
`recv`, and with B the following `connect`, could block forever. *Fix:* both
callers in `dns.cyr` fail closed. These two guards have no test: no test can
make `setsockopt` fail on a fresh socket. That is recorded in-source.

**K — stale integration binary.** `tc_fallback.sh` defaulted to
`build/taar-resolve`. CI rebuilt it, but locally it was a binary dated
2026-08-26 (taar 0.5.0, cyrius 6.5.35). So the local "5/5 pass" results
reported for 0.5.2, 0.6.0 and 0.6.1 tested none of those toolchains. Rebuilt
under 6.7.18 it passed, so no release was broken; the evidence simply wasn't
valid. *Fix:* the script compiles `programs/resolve-smoke.cyr` into a scratch
directory on every run, and wraps each case in a 30 s timeout.

**L — bundle freshness.** CI ran `distlib` and then diffed the result as a
*warning*. *Fix:* `cyrius distlib --check`, which exits 1 when the bundle is
stale.

**M — security job.** It grepped for `"/etc/` (always true: resolv.conf) and
for `syscall(59`, and never failed. Meanwhile CLAUDE.md's rule against syscall
literals was not enforced at all. *Fix:* the job fails on any `syscall(<digit>`
outside a comment in `src/` or `programs/`.

**N — supply chain.**
- `actions/checkout@v4` and `softprops/action-gh-release@v2` were mutable tags;
  the latter is a third-party action holding a write token.
- Both workflows piped cyrius `main`'s `install.sh` into `sh`.
- `release.yml` granted `contents: write` workflow-wide, which reached the
  reusable CI gate too.

*Fix:* both actions SHA-pinned (v4.3.1, v2.6.2), the installer fetched at the
pinned tag (it verifies the release's checksum and Ed25519 signature),
`contents: read` by default, and write only for the release job.

**O — test gaps.** The resolv.conf parser reads text that DHCP clients write
from network-supplied data, and it had no unit test. Nothing pinned the 63-byte
label or 255-byte name limits, or that the in-loop length check stops the
*write*, not just the verdict. Nothing covered the compression loop that only
the hop budget stops (`[label][pointer back to it]`). *Fix:* 47 assertions in
eight new groups, 93 → 140. The name test uses a canary past 257 bytes.

**P — stale docs.**
- `dns.cyr` still called the TCP fallback a roadmap item, and said a TCP
  timeout reads as 0.
- `main.cyr` said both socket-bearing modules carry an AGNOS arm.
- The manifest description said socket and DNS were still to come.
- The test-file header predated socketpairs and the harness, and
  `fake_dns.py` pointed at a `run.sh` that does not exist.
- state.md listed the soft bundle check as gated.
- The roadmap carried a closed item, and claimed the stdlib has no `sendto`
  wrapper (it has since 6.6.5).

All corrected.

**Q — refactor.**
- The two Linux `set_timeout` bodies were identical; they now share
  `_taar_set_sock_timeout`.
- The 2-byte `getrandom` draw existed three times; one shared
  `_taar_plat_random_u16` now feeds the query ID and the AGNOS ephemeral port.
- `5000`, `2048` and `304` became named constants. Array sizes stay literal,
  because the compiler requires it.

## Deferred

Each is in [`roadmap.md`](../development/roadmap.md) with what it waits on.

| Item | Why not now |
| --- | --- |
| AGNOS per-socket state (a resolve can disturb a consumer's socket) | a state-model rewrite needs executed AGNOS coverage (0.7.0) |
| AGNOS EOF vs reset (`sock_recv#49` answers -1 for both) | needs the kernel to tell them apart |
| AGNOS no-connection guard on send / recv | a guard needs a test; AGNOS has none yet |
| a total per-resolve deadline | no monotonic clock in the consumers' stdlib |
| answer owner-name / CNAME-chain validation | feature work; glibc checks, musl does not |
| nameserver failover, `options timeout/attempts` | feature work |
| EINTR retry in the UDP wait | low value alone; lands with failover |
| `MSG_TRUNC` detection | info only; taar sends no EDNS, so replies stay ≤ 512 B |
| missing-resolv.conf default (8.8.8.8 vs 127.0.0.1) | a behaviour decision |
| 0x20 case randomisation vs case-insensitive echo | a decision, pending research |

Accepted as documented: eight forged datagrams from the nameserver's
address, or one spoofed ICMP port-unreachable, can end a resolve early. The
result is a failed resolve, never a wrong answer. The tradeoff is spelled out
at `taar_resolve_ipv4`.

## Benchmarks

`benches/codec.bcyr`, x86_64. The host's timer floor is about 1.3 µs per clock
read, measured and subtracted by `lib/bench.cyr`. Medians of three runs:

| Row | Before | After | |
| --- | ---: | ---: | --- |
| `ipv4_parse` | 55 ns | 57 ns | untouched — noise |
| `ipv4_format_to_buf` | 85 ns | 90 ns | untouched — noise |
| `taar_fill_sockaddr` | 34 ns | 37 ns | untouched — noise |
| `dns_encode_name` | 51 ns | 54 ns | untouched — noise |
| `dns_build_query` | 101 ns | 105 ns | untouched — noise |
| `dns_reply_ok` | 57 ns | 57 ns | untouched |
| `dns_first_a` (CNAME + A) | 87 ns | 99 ns | +12 ns: the class read (G) |
| `resolv_parse` | 311 ns | 330 ns | +19 ns: the CR check (F) |

No optimisation was made, because none is warranted. Every row is tens to
hundreds of nanoseconds on a path that then waits milliseconds on the network.
The hardening costs about 30 ns per resolve. The rows mainly guard against a
parser regression that would make it pathological.
